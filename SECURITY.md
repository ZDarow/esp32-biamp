# Безопасность

## Поддерживаемые версии

| Версия | Поддерживается | Комментарий |
|---|---|---|
| Прошивка v34 | ✅ | Текущая |
| Прошивка v29 – v33 | ✅ | Переполнение кольца устранено, но без последних правок DSP |
| Прошивка v28 и старше | ❌ | Содержат переполнение кольцевого буфера, см. ниже |
| Приложение 1.0 | ✅ | Текущая |

## Известные уязвимости

### Переполнение кольцевого буфера (прошивка v25 – v28)

**Серьёзность:** высокая — повреждение памяти, приводящее к щелчкам и
повреждению звука.

Функции `ringPush()` и `ringPop()` копировали данные одним `memcpy` через
физический конец массива `ring_buf`. При `RING_FRAMES = 4096` и размере
блока 896 кадров запись начиналась с индекса 8190 при длине массива
8192 элементов — выход за границу примерно на 3580 байт с затиранием
соседних статических переменных.

**Затронуто:** прошивка v25 и все более ранние.
**Исправлено в:** v29.
**Рабочее исключение:** v29 и новее, подтверждено самотестом `bad=0`.

Признак заражения: щелчки в динамиках при `RingDrops: 0` и `Underrun 0/0`.

### Падение приложения без разрешения Bluetooth

**Серьёзность:** средняя — отказ в обслуживании, не нарушение данных.

В версии 1.0 до исправления `refreshDevices()` вызывался до выдачи
разрешения `BLUETOOTH_CONNECT` и ронял приложение с `SecurityException`.
Аннотация `@SuppressLint` подавляла проверку линтера, но не исключение.

**Исправлено:** вызов перехватывает `SecurityException`; список устройств
перечитывается из обработчика результата запроса разрешений.

## Как сообщить об уязвимости

**Не создавайте публичный issue.**

Используйте функцию GitHub **Security → Report a vulnerability** на
странице Security репозитория
<https://github.com/ZDarow/esp32-biamp/security/advisories/new>, либо пришлите
письмо напрямую мейнтейнеру: **oleg-mordovkin@yandex.ru**.

Что указать в отчёте:

- Описание уязвимости и её влияние
- Шаги воспроизведения
- Версия прошивки или приложения
- Модель платы и чип ESP32
- Условия, при которых проблема проявляется стабильно

Что полезно приложить: вывод `stats` с COM-порта, дамп `evlog`, лог
приложения — **после удаления из него адресов устройств и личных данных**.

## Что считается уязвимостью

| Категория | Пример |
|---|---|
| Повреждение памяти | Переполнение буфера, запись за пределы массива |
| Потеря или порча аудио | Щелчки, пропуски при нормальных счётчиках |
| Отказ в обслуживании | Падение приложения, зависание тракта |
| Утечка данных | Передача личных данных на сторонние серверы |
| Обход ограничений | Команда, исполняющаяся вне заявленного диапазона |

## Что не считается уязвимостью

| Категория | Пример |
|---|---|
| Потребление ресурсов | Замедление при большом числе подключений |
| Ошибки без последствий | Опечатка в тексте интерфейса |
| Отсутствующая функциональность | «Нет OTA-обновления» |
| Ожидаемое поведение | Команда вне диапазона молча игнорируется — так задумано |

## Публичное раскрытие

Мейнтейнеры придерживаются срока **90 дней** с момента подтверждения
уязвимости до публичного раскрытия, чтобы дать пользователям время обновиться.
