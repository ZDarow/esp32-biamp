# Contributing

Спасибо за интерес к проекту. Этот документ описывает, как внести вклад.

Приняты любые вклады: баг-репорты, исправления, новые возможности,
улучшения документации.

Перед началом прочитайте [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

---

## С чего начать

1. Откройте [Issues](https://github.com/ZDarow/esp32-biamp/issues) и проверьте,
   не обсуждается ли тема уже.
2. Для крупных изменений сначала создайте issue с описанием идеи — так мы
   обсудим подход до того, как вы потратите время на реализацию.
3. Для мелких правок сразу переходите к pull request.

---

## Как разделены направления

Репозиторий разделён по владению путями: у прошивки, приложения Android и
клиента для ПК свои файлы и свои ветки (`firmware-dev`, `android-dev`,
`pc-client-dev`). Правка чужого файла не пройдёт локальный pre-commit-хук.

Перед первой правкой включите его:

```bash
git config core.hooksPath .githooks
```

Правила, список общих файлов и команды слияния — в
[docs/BRANCHING.md](docs/BRANCHING.md).

## Окружение

### Прошивка

| Компонент | Версия |
|---|---|
| [arduino-cli](https://arduino.github.io/arduino-cli/latest/installation/) | свежая |
| ESP32 core | `esp32:esp32` 3.x |
| PowerShell | 5.1 или новее (`powershell` или `pwsh`) |

```bash
arduino-cli core update-index
arduino-cli core install esp32:esp32
arduino-cli lib install "Adafruit GFX Library" "Adafruit SSD1306"

# audio-tools и ESP32-A2DP отсутствуют в реестре Arduino —
# публикуются только на GitHub, поэтому ставятся вручную:
git clone --depth 1 https://github.com/pschatzmann/arduino-audio-tools.git \
  "$(arduino-cli config get directories.user)/libraries/audio-tools"
git clone --depth 1 https://github.com/pschatzmann/ESP32-A2DP.git \
  "$(arduino-cli config get directories.user)/libraries/ESP32-A2DP"
```

### Приложение

| Компонент | Версия |
|---|---|
| JDK | 17 |
| Android SDK | platform 35, build-tools 35.0.0 |
| Gradle | 8.9 (через wrapper) |

Создайте `android-app/local.properties`:

```properties
sdk.dir=C:\\Android\\Sdk
```

## Проверка перед коммитом

Оба компонента обязаны собираться. CI делает то же самое, но локальная
проверка быстрее и экономит время на pull request.

### Прошивка

```powershell
pwsh -File .\firmware\tools\build.ps1
```

### Приложение

```bash
cd android-app
./gradlew assembleDebug
./gradlew lint
```

Скомпилированный APK обязан работать на устройстве: подключиться к
устройству, прочитать `status`, изменить параметр и увидеть отклик.

## Правила оформления коммитов

Коммиты на русском языке, в повелительном наклонении:

```
Исправить переполнение кольцевого буфера при переносе
Добавить логарифмическую шкалу частот для chhp
Обновить документацию под прошивку v34
```

Содержимое коммита — одно логическое изменение. Не смешивайте рефакторинг
с новой функциональностью: их удобнее ревьюить раздельно.

## Что важно знать о проекте

### Источник истины — прошивка

Приложение подстраивается под прошивку, а не наоборот. Прежде чем изменить
формат команды или парсер в `android-app`, сверьтесь с
`firmware/ESP32_BiAmp/ESP32_BiAmp.ino` и разделом 4.4
[документации приложения](android-app/docs/DOCUMENTATION.md).

**Команда, которой нет в прошивке, будет молча проигнорирована устройством.**
Это уже случалось: кнопка отправляла `meta`, которой в прошивке не
существует.

### Диапазоны обязаны совпадать

Значения в интерфейсе не должны выходить за пределы, которые проверяет
`safeCmdVal()` в прошивке. Расхождение даёт ситуацию, когда ползунок
показывает применённое значение, которого на устройстве нет.

Текущий пример: `MAX_DELAY_SAMPLES = 220` при `DELAY_BUF_SIZE = 256`.
Изменение потолка требует правки **обоих** мест.

### Аудиотракт критичен к памяти

Кольцевой буфер — обычный линейный массив, а не кольцо на указателях.
Любое копирование через физический конец переполняет буфер и портит
соседние переменные. Симптомы: треск при нулевых `RingDrops` и `Underrun`.

После любых изменений в тракте обязателен самотест при загрузке:

```
Ring selftest: PASS frames=10752/10752 bad=0 drops=0
```

`bad > 0` означает порчу данных — публиковать такую сборку нельзя.

### Размеры и стили

- Kotlin: отступ 4 пробела, строки до 120 символов
- Скетч: отступ 2 пробела, строки до 100 символов
- Комментарии на русском языке
- Имена переменных и функций — английский, `snake_case` и `camelCase`
- Названия веток — `kebab-case` на английском: `fix/delay-limit`

Правила закреплены в `.editorconfig` и `.gitattributes`.

## Запрещено

- ❌ Коммитить файлы сборки, логи и захваты Bluetooth
- ❌ Коммитить `local.properties` — он содержит локальные пути
- ❌ Публиковать содержимое `*.pcapng` и дампов SPP-сессий: там адреса
  устройств и данные реальных подключений
- ❌ Указывать команды в приложении, которых нет в прошивке
- ❌ Менять протокол SPP без обновления документации в том же коммите

## Pull request

1. Создайте ветку от `main` с понятным именем.
2. Внесите изменения, запустите обе сборки.
3. Обновите документацию, если изменился протокол или поведение.
4. Опишите в PR, что изменилось и **как это проверено** — на каком
   устройстве, с какими счётчиками.
5. Откройте pull request в `main`.

### Хорошее описание PR

```
Исправить переполнение кольцевого буфера при переносе

ringPush копировал данные одним memcpy через физический конец ring_buf.
При RING_FRAMES=4096 и SELFTEST_CHUNK=896 запись стартовала с индекса 8190
при размере массива 8192 элементов — выход за границу ~3580 байт.

Проверка на COM15, прошивка v29 (пример из истории, порт и версия зафиксированы):
- Ring selftest: PASS frames=10752/10752 bad=0 drops=0
- 30 с внутреннего теста: RingDrops: 0, BadSamples: 0, Underrun 0/0
- WR max 8364 мс (было 19414)
```
