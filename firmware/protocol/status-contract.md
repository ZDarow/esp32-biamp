# Контракт протокола v35.1 (источник истины)

Этот файл — **единственный** источник истины для всех трёх реализаций:
прошивки (`firmware/ESP32_BiAmp/ESP32_BiAmp.ino`), Android-приложения
(`android-app/`), PC-клиента (`pc-client/`).

Файл создан вручную по результатам аудита 2026-10-01. Правки вносятся
**только** согласованно во всех трёх реализациях, иначе расхождение
воспроизведётся снова.

## 1. Команды, удалённые в v35 (использовать ЗАПРЕЩЕНО)

| Команда | Поле статуса | Причина удаления |
|---|---|---|
| `inv:<ch>` (`0`/`1`/`off`) | `INV: 0100` | Инверсия фазы заменена перестановкой Л/П |

Любой клиент, отправляющий `inv:`, отправляет команду в пустоту: `dispatchCommand`
не содержит такой ветки, а устройство НЕ отвечает ошибкой. Клиент обязан
удалить и билдеры команд, и парсер поля, и элементы интерфейса.

## 2. Блок `status` — ровно 13 строк, порядок фиксирован

```
V0=40% V1=40% bal=0.00
Fc=400Hz hp=45Hz sub=ON
XO: Butter ON
TLF=0.00dB THF=-1.00dB
EQ: L=0.00 M=0.00 H=0.00
Mute: 0/0
SWP: 0
DUP: 0
BT: ON | SPP: OFF
Src: 44.1 kHz
Test: 0 TVol=4%
CHF: 0/0 0/0 0/0 0/0
Delay: 0/0/0/0
```

Конец блока — строка `Delay:`, последняя по определению.

### Форматы по строкам

| Строка | Формат | Значения | Примечание |
|---|---|---|---|
| 1 | `V0=N% V1=N% bal=F` | N: 0..100 целое; F: 2 знака, Arduino `String(float)` | `bal` может быть `-10.00..10.00` |
| 2 | `Fc=NHz hp=NHz sub=ON\|OFF` | N — **целое** (прошивка печатает `(int)`) | дробная часть `fc_hz` теряется на стороне прошивки |
| 3 | `XO: <Butter\|LR4> <ON\|OFF>` | — | хвост ` ON`/` OFF` обязателен и значим |
| 4 | `TLF=FdB THF=FdB` | F: 2 знака; -6..3 | |
| 5 | `EQ: L=F M=F H=F` | F: 2 знака; -12..12 | ровно один пробел после `EQ:`, затем ` L=`/` M=`/` H=` |
| 6 | `Mute: z0/z1` | каждое — `0` или `1` | **НОВОЕ в v35.1** |
| 7 | `SWP: N` | `0`/`1` | новое в v35 |
| 8 | `DUP: N` | `0` или `1 (z2 == z1, каналы 2,3 не выводятся)` | новое в v35; **`DUP: 0` печатается ВСЕГДА** |
| 9 | `BT: ON\|OFF \| SPP: ON\|OFF` | — | разделитель ` \| ` |
| 10 | `Src: 44.1 kHz` или `Src: 48 kHz` | — | |
| 11 | `Test: N TVol=N%` | N: 0..4; TVol: **0..6** | `TVol` — целое число процентов |
| 12 | `CHF: a/b c/d e/f g/h` | 4 пары, целые | порядок: `HP/LP` для каналов 0,1,2,3 |
| 13 | `Delay: a/b/c/d` | целые, 0..220 | конец блока |

## 3. Команды mute

### v35 (устаревшая, остаётся для совместимости)

```
mute:<z>        → ПЕРЕКЛЮЧИТЕЛЬ. Аргумент игнорируется: muted_z[z] = !muted_z[z]
```

### v35.1 (новая, обязательна для всех клиентов)

```
mute:<z>:<0|1>  → АБСОЛЮТНАЯ установка. z — 0 или 1. Значение обязано
                   соответствовать последующему чтению `Mute: z0/z1`.
```

Требование к прошивке: при `safeCmdVal` с двумя аргументами значение
устанавливается, а не инвертируется. Старый `mute:<z>` обязан продолжать
работать как переключатель — иначе сломаются старые версии обоих клиентов.

## 5. Контрактный тест (обязателен для обоих клиентов)

Каждый клиент обязан иметь тест, который:
1. читает этот файл (или его дословную копию фикстуры),
2. скармливает строки парсеру,
3. проверяет, что распознаны **все 13 полей** и что ни одна строка не
   осталась «нераспознанной».

Тест обязан **падать**, если в блок добавлена новая строка, а парсер её не
знает. Это единственная защита от повторения расхождения.

## 6. Обязательная защита от регрессии

Значение, которое парсер не смог разобрать, **не должно молча заменяться
значением по умолчанию**. Требуемое поведение:
- парсер возвращает признак «поле потеряно» либо сохраняет предыдущее
  значение (Android уже делает это через перегрузку `parse(lines, base)`);
- неизвестные строки блока считаются ошибкой парсинга, а не «дефолтом».
