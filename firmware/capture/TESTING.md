# Тестирование аудиопотока ESP32-S3 сниффером

## Обзор

Этот документ описывает процесс тестирования цифрового аудиотракта ESP32 BiAmp
(Master) с использованием ESP32-S3 в роли сниффера. Сниффер читает оба I²S-порта
Master в подчинённом режиме и передаёт захваченные данные по нативному USB для
анализа на ПК.

## Оборудование

### Подключение

| Сигнал | Master (ESP32) | S3 (ESP32-S3) |
|---|---|---|
| I²S0 DOUT (Z1) | GPIO2 | `CAP_Z1_DATA` = GPIO17 |
| I²S0 LRCK (Z1) | GPIO15 | `CAP_Z1_LRCK` = GPIO18 |
| I²S0 BCLK (Z1) | GPIO4 | `CAP_Z1_BCK` = GPIO16 |
| I²S1 DOUT (Z2) | GPIO26 | `CAP_Z2_DATA` = GPIO41 |
| I²S1 LRCK (Z2) | GPIO27 | `CAP_Z2_LRCK` = GPIO40 |
| I²S1 BCLK (Z2) | GPIO25 | `CAP_Z2_BCK` = GPIO42 |
| GND | GND | GND |

Обязательна общая земля — без неё уровни 3.3 В не определены. Питание S3 —
отдельное USB.

### COM-порты

| Порт | Устройство | Назначение |
|---|---|---|
| COM8 | ESP32 (CH340) | Master: команды, `stats`, `status` |
| COM11 | ESP32-S3 (CH9102) | S3 UART: прошивка, boot-лог |
| COM12 | ESP32-S3 (нативный USB) | S3 команды `PING`/`START`/`STOP` + двоичный поток |

> ⚠️ Открытие COM8 дёргает DTR/RTS и перезагружает Master. Захват и `stats`
> снимаются в одной сессии. COM11 не открывать через pyserial без управления
> DTR/RTS: RTS сбрасывает S3.

## Сборка и прошивка

### Master (ESP32)

```powershell
pwsh -File .\firmware\tools\build.ps1
pwsh -File .\firmware\tools\flash.ps1 -Port COM8
```

### Сниффер (ESP32-S3)

```powershell
# Требуется ESP-IDF 6.0 (проверено на 6.0.2)
& "$env:IDF_PATH\export.ps1"
idf.py -C firmware/capture build
idf.py -C firmware/capture -p COM11 flash
```

## Запуск захвата

### Зависимости

```powershell
py -3.14 -m pip install pyserial numpy
```

### Сценарии

Все сценарии задаются в `firmware/tools/capture-analyze.py` (словарь `SCENARIOS`).
Во всех сценариях тон задаётся через `test:all` (режим 1), а не `test:1` (режим 6):
`test:1` кормит только канал 1 (НФ-ветка Z1), и половина отчёта получается пустой.

| Сценарий | Команды Master | Что проверяет |
|---|---|---|
| `silence` | `dup:0 test:off` | Шумовая полка, смещение, дрейф |
| `dup` | `dup:1 tvol:4 tf:1000 test:all` | Побайтовое совпадение зон |
| `zones` | `dup:0 delay0..3:0 tvol:4 tf:100 test:all` | Смещение между зонами |
| `tone-low` | `dup:0 tvol:4 tf:100 test:all` | Тон ниже кроссовера (НФ-ветка) |
| `tone-high` | `dup:0 tvol:4 tf:5000 test:all` | Тон выше кроссовера (ВЧ-ветка) |
| `anti` | `dup:0 tvol:4 tf:1000 test:anti` | Инвертированная фаза |
| `sweep` | `dup:0 tvol:4 test:sweep` | АЧХ четырёх выходов |
| `delay` | `dup:0 delay2:64 tvol:4 tf:100 test:all` | Задержка DSP 64 отсчёта |
| `clip` | `dup:0 tvol:6 tf:1000 test:all` | Клиппинг при максимальном уровне |

### Запуск

```powershell
# Захват и анализ одного сценария
py -3.14 firmware/tools/capture-analyze.py --sniffer COM12 --master COM8 --scenario dup

# Разбор готового файла без платы
py -3.14 firmware/tools/capture-analyze.py --analyze captures/dup-…/capture.wav --scenario dup

# Список сценариев
py -3.14 firmware/tools/capture-analyze.py --list-scenarios
```

### Повтор захвата при браке пути измерения

`capture_retry()` перезаписывает захват, пока в каналах нет одиночных выбросов
(щелчков). Порог `CLICK_GATE = 0` (чистый захват щелчков не содержит), максимум
`MAX_CAPTURE_ATTEMPTS = 8`. Сценарий `clip` повтором не пользуется — клиппинг там
и есть предмет измерения.

## Интерпретация результатов

### Обязательные счётчики

После **любого** изменения тракта в `stats` Master обязаны быть нулями:

```
RingDrops: 0  SelfTestErr: 0
Underrun Z1=0 Z2=0
Clips 0/0/0/0
Ring selftest: PASS frames=…/… bad=0 drops=0
```

`bad > 0` — порча данных, такую сборку публиковать нельзя.

### Решающий тест `dup:1`

В режиме `dup:1` оба I²S-порта Master несут **побайтово один и тот же буфер**.
Если выбросы видны только в одной зоне — дефект не в Master, а на проводе или
в приёме I²S на S3. Это эталон локализации: он отделяет брак тракта Master от
брака пути измерения.

### Побайтовое совпадение

В `dup:1` побайтовое совпадение показывает ~99.6% расхождения (сдвиг ~2 отсчёта).
Это **не дефект**, а ограничение выравнивания: две зоны читаются независимыми
DMA и `i2s_channel_read`, поэтому момент соответствия кадров зон от прогона к
прогону гуляет на десятки отсчётов. На уровни/фазу/THD не влияет.

### Щелчки

Щелчки определяются по разрыву между соседними отсчётами: `CLICK_JUMP = 0.35 *
FULL_SCALE = 11469`. Чистый захват не содержит щелчков вовсе: тон и развёртка на
уровне теста (tvol:4) дают разрыв соседних отсчётов не выше ~4000, а порог щелчка
— 11469. Поэтому чистота = ноль щелчков.

### Известные ограничения

- **Межзонный сдвиг DMA.** Две зоны читаются независимыми DMA — абсолютная
  межзонная задержка не измеряется. Измеряется **разность** задержек двух каналов
  одной зоны.
- **Ось АЧХ по развёртке.** Анализатор предполагает, что захват начинается с
  `sweep_phase = 0`, а фактически старт сдвинут (~2.2 с). Требует автоопределения
  сдвига.
- **Частота не измеряется на плате.** Подчинённый режим берёт такт с провода, и
  настоящую частоту знает только ПК (по опорному тону).
- **USB 12 Мбит/с.** 4 канала × 16 бит × 44100 Гц = 352.8 КБ/с — запас есть, но
  при 48000 Гц (384 КБ/с) он меньше.
- **Кольцо зоны 2048 кадров (46 мс).** Если USB занят дольше, кадры отбрасываются
  и это видно в `dropped_z*` трейлера.
