# Сниффер цифрового выхода Master (ESP32-S3)

Второй ESP32 (ESP32-S3-DevKitC-1), который параллельно читает оба I²S-потока
Master в подчинённом режиме, склеивает их в один 4-канальный поток и отдаёт
по нативному USB. Настройки Master, прошивка и протокол не меняются —
измеряется ровно то, что физически уходит на провода.

Аудит цифрового тракта, проведённый этим сниффером (состав тракта, методика,
результаты, устранённый дефект зоны Z1) — в `AUDIT.md`.

## Назначение

Аудит цифрового тракта Master:

- согласованность четырёх каналов (задержки, фазы, амплитуды);
- кроссовер: частота среза и пульсация НЧ/ВЧ-веток;
- DSP: АЧХ, THD, клиппинг, щелчки;
- реальная частота дискретизации (по опорному тону тест-сигнала).

Аналоговый выход PCM5102A этим сниффером не измеряется — он проверяется
отдельно, через линейный вход ПК.

## Подключение

| Master (ESP32 WROOM-32) | ESP32-S3-DevKitC-1 |
|---|---|
| GPIO2  I²S0 DOUT (зона Z1) | `CAP_Z1_DATA` = GPIO17 |
| GPIO15 I²S0 LRCK (зона Z1) | `CAP_Z1_LRCK` = GPIO18 |
| GPIO4  I²S0 BCLK (зона Z1) | `CAP_Z1_BCK` = GPIO16 |
| GPIO26 I²S1 DOUT (зона Z2) | `CAP_Z2_DATA` = GPIO41 |
| GPIO27 I²S1 LRCK (зона Z2) | `CAP_Z2_LRCK` = GPIO40 |
| GPIO25 I²S1 BCLK (зона Z2) | `CAP_Z2_BCK` = GPIO42 |
| GND | GND |

Обязательна общая земля — без неё уровни 3.3 В не определены. Питание S3 —
отдельное USB. Выводы S3 выбраны так, чтобы не задеть служебные (19/20 —
нативный USB, 26–32 — флеш и PSRAM, 43/44 — UART0, 45/46 — boot, 0 — кнопка
загрузки). Если разводка платы другая, правятся только константы в
`main/capture_pins.h`.

Вход подчинённого режима имеет высокое сопротивление и нагрузку на источник
не меняет.

## Каналы

Порядок в потоке: `0` — Z1 левый (НЧ), `1` — Z1 правый (ВЧ), `2` — Z2 левый,
`3` — Z2 правый. Формат: 4 канала × 16 бит = 8 байт на кадр.

## Сборка

Требуется ESP-IDF 6.0 (проверено на 6.0.2).

Путь к ESP-IDF задаётся переменной окружения `IDF_PATH`, а активация
окружения — `export.ps1` из каталога установки. Абсолютные пути в
документации не приводятся намеренно: они работают только на одной машине.

```powershell
& "$env:IDF_PATH\export.ps1"
idf.py -C firmware/capture build
```

Результат: `firmware\capture\build\esp32_biamp_capture.bin`.

Прозшив:

```powershell
idf.py -C firmware/capture -p COMx flash
```

## Два USB-порта платы

У ESP32-S3-DevKitC-1 два разъёма, и их нельзя путать — иначе команда не
получит ответа, а причина будет выглядеть как «плата мертва».

| Разъём | Что это | Что через него ходит |
|---|---|---|
| **UART** (CH9102, VID `1A86`) | мост USB-UART на GPIO43/44 | `ESP_LOGI`, boot-лог, паника |
| **USB** (нативный, GPIO19/20) | USB Serial/JTAG | команды `PING`/`INFO`/`START`/`STOP` и весь двоичный поток |

Команды читаются только через нативный USB. Если подключён лишь разъём UART,
`PING` уйдёт в UART0, где его никто не слушает, и ответа не будет — это
не поломка.

Диагностика идёт через `ESP_LOGI`, а не через `printf`: логи уровня INFO
гарантированно видны в мониторе.

## Команды

Управление — ASCII-строки с `\n` по нативному USB (115200 не требуется —
нативный USB Serial/JTAG):

| Команда | Ответ |
|---|---|
| `PING` | `PONG` |
| `INFO` | строка с конфигурацией |
| `START <секунды>` | заголовок 32 Б → кадры → трейлер 32 Б → `END ...` |
| `STOP` | досрочное завершение захвата |

## Формат файла

```
[заголовок 32 Б][кадры: 8 Б × N][трейлер 32 Б]
```

Заголовок: `magic "BAM1"`, версия, каналы=4, биты=16, объявленная частота
(44100 — только для делителей MCLK драйвера, не измерение), `frame_bytes=8`.

Трейлер: `frames`, `dropped_z1`, `dropped_z2`, `max_skew_frames`, `errors`,
`elapsed_ms`, `magic "END1"`. Счётчики в трейлере нужны, чтобы отличить
дефект Master от повреждения захвата: `dropped > 0` или `max_skew` больше
единиц — запись не годится для фазовых измерений.

Первые 2048 кадров после `START` выбрасываются (прогрев): в момент включения
DMA может поймать половину кадра, и один сдвиг на слот в начале файла портит
все измерения фазы.

## Анализ на ПК

```powershell
# Команды даны от корня репозитория
py -3.14 firmware/tools/capture-analyze.py --analyze capture.bin --scenario sweep
```

Сценарии: `dup` (дублирование канала), `silence`, `tone-low`, `tone-high`,
`anti`, `sweep`, `delay`, `clip`. Зависимости: `pyserial`, `numpy`.

Анализатор считает peak/RMS/dBFS, шум, смещение, crest, межканальные
задержки, THD+SINAD, реальную частоту дискретизации, АЧХ по развёртке,
пропуски и щелчки; пишет `capture.wav`, `report.md`, `report.json`.

## Ограничения

- Частота дискретизации не измеряется на плате: подчинённый режим берёт такт
  с провода, и настоящую частоту знает только ПК (по опорному тону).
- USB Serial/JTAG — 12 Мбит/с: 4 канала × 16 бит × 44100 Гц = 352.8 КБ/с,
  запас есть, но при 48000 Гц (384 КБ/с) он меньше.
- Кольцо зоны — 2048 кадров (46 мс): если USB занят дольше, кадры
  отбрасываются и это видно в `dropped_z*` трейлера.
- Тик FreeRTOS — 1 мс (`CONFIG_FREERTOS_HZ=1000`). При стандартных 10 мс
  задержки в 1–2 мс округляются до нуля тиков, а `vTaskDelay(0)` не уступает
  CPU: задача с приоритетом 4 задавливает `main`, и плата замолкает, не
  печатая ни строки. Отсюда же `cap_delay_ms()` — он не даёт задержке
  превратиться в ноль.
- Сторож проверяет только явно подписанные рабочие задачи
  (`zone_task`, `packer_task`, `console_task`): каждая подписывается сама и
  сбрасывает счётчик в начале цикла. Проверка IDLE-задач отключена — на S3 с
  задачами, закреплёнными за ядрами, IDLE до сброса не добирается, и паника
  была бы ложной.
