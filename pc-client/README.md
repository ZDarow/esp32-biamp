# Управление ESP32 Bi-Amp с ПК

Локальная среда для настройки усилителя с компьютера: командная строка и
веб-панель в браузере. Работает по двум каналам, которые прошивка принимает
одновременно — USB-CDC и Bluetooth SPP.

Формат команд и разбор ответов соответствуют `firmware/protocol/status-contract.md`
— это единственный источник истины, общий для прошивки, Android-приложения и
этого клиента. Клиент проверяет его тестом `tests/test_contract.py`, который
читает блок `status` прямо из файла контракта и падает, если в блоке появится
строка, которую парсер не знает.

Инверсия фазы (`inv:`) удалена в v35 и заменена перестановкой Л/П (`swap:`,
поле `SWP:`) и дублированием зоны (`dup:`, поле `DUP:`). Клиент их не знает.

## Требования

- Python 3.10 или новее (проверено на CPython 3.10–3.14)
- `pyserial>=3.5,<4` — единственная внешняя зависимость; веб-панель собрана
  на стандартной библиотеке

## Установка

```powershell
.\setup.ps1
```

Скрипт проверяет версию Python, создаёт `.venv`, ставит зависимости, проверяет
импорт модулей и прогоняет тесты.

## Подключение усилителя

**По USB-CDC.** При подключении кабелем Windows создаёт COM-порт,
например `COM14`. Порт виден сразу, спаривать ничего не нужно.

```powershell
.\run.ps1 -Command ports
.\run.ps1 -Command status
```

**По Bluetooth SPP.** Спарить усилитель в настройках Windows
(«ESP32 BiAmp Speaker»), затем включить **«Свойства» → вкладка «Порты»**
и отметить нужный COM-порт. После этого он появится в `ports`. Скорость
для SPP игнорируется — соединение не последовательное, но параметр
обязателен для совместимости с USB.

Пока COM-порт не создан, проверять инструмент можно через TCP:

```powershell
python -m biamp --port tcp://127.0.0.1:9000 status
```

## Веб-панель

```powershell
.\run.ps1 -Command web -Port COM14
.\run.ps1 -Command web -Port COM14 -Bind 192.168.1.10 -WebPort 8765
```

Открыть `http://127.0.0.1:8765`. Панель показывает текущие параметры,
изменяет их и отправляет команды сразу при отпускании ползунка.
Раз в 15 секунд состояние перечитывается автоматически.

По умолчанию слушает только `127.0.0.1`.

### Защита панели

Панель управляет усилителем, поэтому сервер защищён от запросов с чужих
страниц вашего браузера:

- при старте генерируется токен, он печатается в консоль и подставляется в
  страницу автоматически; все запросы к `/api/*` обязаны слать его в
  заголовке `X-BiAmp-Token`;
- проверяются `Host` (защита от DNS-rebinding) и `Origin`;
- `Content-Type` обязан быть `application/json` — простой cross-origin POST с
  `text/plain` отбивается;
- у `/api/command` белый список: `status`, `stats`, `help`, `save`,
  `preset:0..3`, `test:<режим>`. `factory` и `reboot` из браузера не доступны;
- заголовки `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: no-referrer`;
- изменение настроек пишется в журнал (`audit:` в stderr).

При запуске с не-loopback `--host` печатается предупреждение: ограничивайте
доступ файрволом.

## Команды CLI

| Команда | Действие |
|---|---|
| `ports` | Список COM-портов |
| `status` | Текущие настройки, `--json` для вывода машинно |
| `set <имя> <значение>` | Изменить один параметр |
| `raw <команда>` | Отправить команду прошивки как есть |
| `test <режим>` | Тест-сигнал: `off`, `all`, `left`, `right`, `anti`, `sweep`, `1`–`4` |
| `save <имя>` | Сохранить настройки в профиль |
| `load <имя>` | Применить профиль, `--nvs` — с записью в NVS |
| `web` | Локальная веб-панель, `--host`, `--web-port` |

Профили лежат в `%USERPROFILE%\.biamp\profiles\`.

```powershell
.\run.ps1 -Command save studio
.\run.ps1 -Command load studio -nvs
```

## Параметры для `set`

`volume`, `balance`, `tilt_low`, `tilt_high`, `crossover`, `sub_hp`,
`sub`, `xo_on`, `crossover_type`, `lr_swap`, `dup_out`, `mute0`, `mute1`,
`test_volume`, `test_freq`.

Логические параметры (`sub`, `xo_on`, `lr_swap`, `dup_out`, `mute0`, `mute1`)
принимают `true`/`false`, `on`/`off`, `1`/`0`, `да`/`нет` — регистр не важен.
Молчаливого `bool("false")` не бывает: непонятное значение даёт ошибку.

Диапазоны проверяются на стороне клиента по таблице раздела 4 контракта:
значение вне допустимого не уйдёт на устройство, а вернётся ошибка. Это важно
— прошивка молча игнорирует часть некорректных значений. В частности
`test_volume` ограничен 0..6 (`TEST_VOL_MAX = 0.06f`), а `mute0`/`mute1`
шлют абсолютную установку `mute:<z>:<0|1>`, а не переключатель.

## Структура

```
pc-client/
  biamp/
    protocol.py   команды с валидацией, парсер status, сборка настроек
    transport.py  COM-порт, TCP, эмулятор для тестов
    client.py     чтение состояния, применение настроек
    cli.py        командная строка, профили
    webapp.py     HTTP-сервер и API
    static/       веб-панель
  tests/          80 тестов, железа не требуют
```

## Проверка без устройства

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t .
```

Тесты не обращаются к железу: `LoopbackTransport` имитирует прошивку,
эмулятор по TCP отвечает настоящим форматом `status` из контракта.

## Ограничения

- `evlog` доступен только по USB — по SPP прошивка его не отдаёт.
- Смена задержки обнуляет линию задержки: после команды возможен короткий
  щелчок. Это поведение прошивки, а не инструмента.
- Значения `ch_hp`/`ch_lp` в диапазоне 1–19 Гц прошивка поднимает до 20 Гц;
  клиент повторяет это приглаживание заранее.
- `DUP: 1` не сохраняется в NVS и сбрасывается при перезагрузке усилителя.
- Частичный блок `status` не заменяет ранее прочитанные значения дефолтами:
  клиент мержит его поверх предыдущего состояния и отдельно сообщает о
  нераспознанных строках.
