# Математика DSP: кроссоверы, EQ, задержки, анти-клик и метрики

Версия: v35.1 (соответствует прошивке irmware/ESP32_BiAmp/ESP32_BiAmp.ino).

Цель документа — дать контрибьюторам единую точку отсчёта по формулам биквадов, логике кроссовера, работе задержек, рампам гашения и метрикам щелчка (click_start_max/click_fade_max).
## 1. Биквады (RBJ). Функция calcSectionTo()

В прошивке calcSectionTo(out_cb[][3], out_ca[][2], sec, type, f, q, db) реализует стандартные биквады RBJ (Audio EQ Cookbook). Коэффициенты нормируются на a0: out_cb[sec][0]=b0/a0, 1/a0, 2/a0, out_ca[sec][0]=a1/a0, out_ca[sec][1]=a2/a0.

### 1.1 Типы секций
|---|------------|------------|
| 0 | Lowpass (LPF) | ФНЧ |
| 1 | Highpass (HPF) | ФВЧ |
| 2 | Peaking EQ | Полосовой эквалайзер |
| 3 | Lowshelf | Низкочастотный полочковый |
| 4 | Highshelf | Высокочастотный полочковый |
| 5 | Bypass | Единичный коэффициент (flat) |
| type | Назначение | Примечание |
|---|------------|------------|
| 0 | Lowpass (LPF) | ФНЧ |
| 1 | Highpass (HPF) | ФВЧ |
| 2 | Peaking EQ | Полосовой эквалайзер |
| 3 | Lowshelf | Низкочастотный полочковый |
| 4 | Highshelf | Высокочастотный полочковый |
| 5 | Bypass | Единичный коэффициент (flat) |

### 1.2 Общие формулы (RBJ)

Для всех секций:
- ?0 = 2·?·f/SAMPLE_RATE
- cos ?0, sin ?0
- ? = sin ?0 / (2·q)

LPF (type 0): b0 = (1-cos ?0)/2, b1 = 1-cos ?0, b2 = (1-cos ?0)/2; a0=1+?, a1=-2*cos ?0, a2=1-?
HPF (type 1): b0=(1+cos ?0)/2, b1=-(1+cos ?0), b2=(1+cos ?0)/2; a0=1+?, a1=-2*cos ?0, a2=1-?
Peaking (type 2): A=10^(db/40), b0=1+?*A, b1=-2*cos ?0, b2=1-?*A; a0=1+?/A, a1=-2*cos ?0, a2=1-?/A
Lowshelf (type 3), Highshelf (type 4): по Audio EQ Cookbook (shelving)

## 2. Кроссовер

- c_hz — частота среза кроссовера (ВЧ>СЧ, СЧ>НЧ)
- xo_on — выключает разделение на НЧ/ВЧ (ставит секции 1..4 в bypass), сабсоник и полосные фильтры остаются.
## 2. Кроссовер

- fc_hz - частота среза кроссовера (ВЧ->СЧ, СЧ->НЧ)
- sub_hz - частота среза сабсоника (HPF на сабвуфер)
- xo_type=1 - Butterworth 2-го порядка (один биквад на полосу)
- xo_type=2 - LR4 (4-й порядок), реализован двумя биквадами на каждую ветку
- xo_on - при false секции 1..4 переводятся в bypass, сабсоник и полосные фильтры остаются

## 3. Задержки

- ch_delay[c] - задержка канала в отсчетах (0..MAX_DELAY_SAMPLES)
- DELAY_BUF_SIZE = 256 - размер кольцевого буфера задержки на канал
- MAX_DELAY_SAMPLES = 220 - потолок команды delay (лимит UI согласован с прошивкой)
- Разница 256-220 = 36 отсчетов - запас, чтобы нельзя было выйти за границы кольца при переносе через физический конец массива и при смене задержки

## 4. Рампы, анти-клик, fadeOutDsp

- resetDspState() - сброс состояний биквадов (st1/st2/chst), обнуление линий задержки, обнуление gain, инициализация замера щелчка старта (click_probe_armed)
- fadeOutDsp() - плавное сведение в ноль перед остановкой потока (DMA не должен замереть на ненулевом отсчете), измеряет щелчок при остановке
- RAMP_K = 0.001f, FADE_K = 0.005f, FADE_EPS = 5.0e-4f (-66 дБ от полной шкалы), FADE_MAX_FRAMES = 2048

## 5. Метрики щелчка (click_start_max / click_fade_max)

- click_probe / click_probe_armed - окно измерения первых/последних кадров для оценки старта/остановки потока
- click_start_max[2] - максимум амплитуды в окне старта потока по каналам
- click_fade_max[2] - максимум амплитуды в окне фейда при остановке
- Команда click в прошивке считывает эти значения и возвращает их для отладки I2S_WRITE_TIMEOUT_MS/рамп

## 6. EQ

- Три полосы: low (sect 5), mid (sect 6), high (sect 7) в calcAllFilters()
- Диапазоны: low ±12 дБ, mid ±12 дБ, high ±12 дБ (см. команды EQ в DOCUMENTATION.md)
- TLF/THF (tilt) применяются после EQ в виде множителей (p.tlf, p.thf)

## 7. Связь с UI и безопасностью лимитов

- Лимиты UI не должны превышать проверки прошивки. Android: DELAY_MAX = 220 в Protocol.kt соответствует MAX_DELAY_SAMPLES = 220 в прошивке.
- Запас буфера (256-220) критичен из-за кольцевой природы delay_buf[4][DELAY_BUF_SIZE] и механики переноса через конец массива (v29).

## 8. Проверка целостности

После любых изменений DSP обязательно проверять на живом устройстве: Ring selftest: PASS frames=10752/10752 bad=0 drops=0, RingDrops: 0, BadSamples: 0, Underrun Z1=0 Z2=0, Clips 0/0/0/0.
