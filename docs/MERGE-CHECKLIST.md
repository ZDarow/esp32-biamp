# Чек-листы безопасного слияния

Документ собирает проверки, которые обязаны пройти
перед тем, как изменение считается готовым к слиянию
в `main`. Цель — ни одна строка не потеряется, ни
одна логическая связь не нарушится.

Контекст: стратегия ветвления — `docs/BRANCHING.md`,
порядок проверок по направлениям — `docs/TESTING.md`.

---

## Общий чек-лист (любое направление)

Перед слиянием ветки задачи в ветку направления и
ветки направления в `main`:

- [ ] **Линейная история.** `git log --merges main`
      не показывает новых merge-коммитов. `main`
      двигается только `--ff-only`.
- [ ] **Свои пути.** Коммит затрагивает только файлы
      своего направления и общие файлы. Хук
      `.githooks/pre-commit` не отказал.
- [ ] **Сборка.** Компонент направления собирается
      без ошибок (команды — `docs/TESTING.md`).
- [ ] **Тесты.** Юнит-тесты зелёные; инструментированные
      — прогнаны на устройстве, если менялось
      поведение на Android-рантайме.
- [ ] **Документация.** Изменился протокол, формат
      `status`, лимит значения — документация и все
      три реализации обновлены в том же коммите.
- [ ] **Общие файлы отдельно.** Правки `README.md`,
      `AGENTS.md`, `docs/**` и прочих общих файлов
      вынесены в отдельный маленький коммит.
- [ ] **Стиль.** Отступы, длина строк, переводы строк
      (только LF в индексе) — `.editorconfig`,
      `.gitattributes`.
- [ ] **Нет мусора.** Нет `TODO`, заглушек, отладочного
      `print()`, закомментированного кода, секретов,
      `local.properties`, логов, `*.pcapng`.

## Слияние направления в `main`

Порядок действий:

```bash
git checkout <направление>-dev
git fetch origin
git rebase origin/main          # конфликт возможен только в общих файлах
git push --force-with-lease origin <направление>-dev
git checkout main
git merge --ff-only <направление>-dev
git push origin main
```

- [ ] `rebase` не поднял конфликт в чужих путях (если
      поднял — стоп, задача разбита неправильно).
- [ ] Конфликт в общем файле решён с сохранением правок
      обеих сторон.
- [ ] `--force-with-lease`, не `--force`.
- [ ] `git merge --ff-only` прошёл без merge-коммита.
- [ ] После пуша CI гигиены зелёный: секреты, LICENSE,
      запрещённые файлы, переводы строк, матрица
      владения (`tools/check-owners.ps1`).

## Парная задача (два направления сразу)

Пример — кубическая громкость (issue #6): прошивка +
приложение. Порядок обязателен:

1. [ ] Согласование владельцев направлений до начала
       работы.
2. [ ] Сначала прошивка: `vol_z` в `ESP32_BiAmp.ino`,
       контракт, документация.
3. [ ] Потом приложение: `StatusParser`, `VolumeTab`,
       тесты.
4. [ ] Каждое направление сливается в `main`
       самостоятельно, по своему чек-листу.
5. [ ] Проверка на устройстве: показания ползунка
       совпадают с применённым значением.

## Откат

Если после слияния обнаружен дефект:

- [ ] `git revert <коммит>` в `main` — не переписывать
      опубликованную историю.
- [ ] Ветка направления откатывается `rebase` на
      исправленный `main`, затем `--force-with-lease`.
- [ ] В отчёте о дефекте: симптом, счётчики, воспроизведение.
