# Конвенции репозитория

Единый справочник по стилю, именованию и правилам коммитов.
Конкретные факты по каждому направлению — в `AGENTS.md` соответствующей
директории (`android-app/AGENTS.md`, `firmware/AGENTS.md` — при появлении).

---

## 1. Структура веток (GitFlow-lite)

```
main                       — защищённая ветка, только релизы (--no-ff merge)
├── firmware-dev            — прошивка ESP32 (Arduino C++)
├── android-dev             — Android-приложение (Kotlin / Compose)
├── pc-client-dev           — клиент ПК (Python)
└── verify-dev              — проверки и измерения (сниффер, хост-тесты DSP)

feature/<направение>/<описание>   — новая функциональность
release/v<X.Y>                    — подготовка релиза
hotfix/v<X.Y>                     — срочное исправление на релизе
```

**Правила:**
- Ветки-направления сливаются в `main` через PR.
- `main` — только релизы, `--no-ff` merge.
- Теги: `v<X.Y.Z>` на `main`, changelog в `docs/CHANGELOG.md`.
- Резервные копии веток перед сносом — через `git tag`, а не через ветку `backup/`.
- Никаких веток `backup/*` в репозитории.

## 2. Именование веток

- `kebab-case`, только строчные буквы, цифры, дефис.
- Формула: `<тип>/<направение>/<описание>`.
- Примеры: `fix/delay-limit`, `feature/android/adaptive-navigation`,
  `hotfix/v35.1/fix-status-parser`.
- Запрещены: пробелы, слэши в середине, заглавные буквы, подчёркивания.

## 3. Коммиты

- **Язык:** русский, повелительное наклонение.
- **Один коммит — одно логическое изменение.**
- Примеры:
  - `Исправить переполнение кольцевого буфера при переносе`
  - `Добавить контрактный тест для Limits`
  - `Обновить документацию: протокол v35.1`
- Запрещены:
  - Коммиты без компиляции обоих компонентов (прошивка + приложение).
  - Коммиты с `WIP`, `fixme`, `TODO` в коде.
  - Коммиты `.env`, `*.pem`, `*.key`, `credentials.json`.

## 4. Код

| | Отступ | Длина строки |
|---|---|---|
| Kotlin | 4 пробела | 120 |
| C++ (скетч) | 2 пробела | 100 |
| Python | 4 пробела | 100 |
| YAML / Markdown | — | 100 |

- Имена переменных и функций — английские, `camelCase` / `snake_case`.
- Комментарии и документация — на русском, объясняют «почему», а не «что».
- Никаких `print()` для отладки, `TODO`, заглушек.

## 5. Документация

- Все изменения протокола — в одном коммите с кодом.
- Источник истины по протоколу — `firmware/protocol/status-contract.md`.
- `firmware/DOCUMENTATION.md` — общая документация прошивки, не дублирует
  контракт: раздел 4 содержит **ссылку** на `protocol/status-contract.md`.
- `android-app/docs/DOCUMENTATION.md` — документация приложения, раздел 4.4
  описывает формат `status`.
- `docs/CHANGELOG.md` — ведётся при каждом релизе.

## 6. Проверка перед коммитом

См. `docs/CHECKLIST.md` — чек-лист, который проверяет `.githooks/pre-commit`.

## 7. Игнорируемые файлы

См. `.gitignore`. Ключевые правила:
- Кэши (`.mypy_cache/`, `.ruff_cache/`, `.pytest_cache/`, `.gradle/`,
  `.kotlin/`, `build/`) — не коммитятся.
- Секреты (`.env`, `*.p12`, `*.jks`, `*.keystore`, `local.properties`) —
  только в секретах GitHub.
- Захваты Bluetooth (`*.pcap`, `*.pcapng`) и WAV — никогда не коммитятся.
- `.vscode/settings.json` и `.vscode/tasks.json` — коммитятся, остальное
  `.vscode/` игнорируется.
