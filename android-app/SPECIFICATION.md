# 📝 ТЗ «BiAmp Control» — адаптация под **VSCode + Windows**

Ниже — **полный обновлённый вариант ТЗ**. Изменения относительно версии под Linux/Android Studio помечены 🔧. Протокол устройства и логика не тронуты.

---

## 1. Назначение и рамки

**Цель:** приложение-пульт для bi-amp колонки на ESP32 по классическому Bluetooth (SPP/RFCOMM), с ползунками и тёмной темой. Протокол устройства — текстовые команды (уже в прошивке); **прошивку и протокол не менять**.

**Целевой смартфон:** Redmi Note 9 Pro (miatoll), LineageOS, Android 15, API 35.
🔧 **Рабочая станция разработки:** ПК с **Windows**, редактор **VSCode**. Сборка — через **Gradle из командной строки** (без Android Studio).

## 3. Справочник протокола устройства (источник истины)

### 3.1. Транспорт
- Профиль **SPP (RFCOMM)**, UUID `00001101-0000-1000-8000-00805F9B34FB`.
- Имя устройства: `ESP32 BiAmp Speaker` (сопряжено заранее).
- Команды — строки в нижнем регистре, терминатор `\n` (устройство принимает и `\r`). Макс. длина строки — 64 символа.
- Большинство команд **без ответа**. С ответом: `status` (7 строк), `stats`, `meta`, `heap`, `help`, `Preset applied`, `Test mode: N`, `Saved`, `Factory reset`.

### 3.2. Команды

| Команда | Диапазон | Назначение |
|---|---|---|
| `vol:0-100` | % | громкость обеих зон |
| `v0:0-100`, `v1:0-100` | % | громкость зоны Л/П |
| `bal:-10..10` | шаг 1 | баланс (− влево) |
| `mute:0`, `mute:1` | — | тумблер mute зоны |
| `fc:200-1000` | Гц, шаг 50 | частота кроссовера |
| `hp:20-80` | Гц, шаг 5 | частота сабсоника |
| `sub:0/1` | — | сабсоник вкл/выкл |
| `tlf:-6..3`, `thf:-6..3` | дБ, шаг 0.5 | трим НЧ/ВЧ |
| `eql/-12..12`, `eqm`, `eqh` | дБ, шаг 1 | эквалайзер |
| `swap:0/1` | — | перестановка Л/П |
| `dup:0/1` | — | дублирование выходов 2,3 |
| `preset:0-3` | — | Flat/Voice/Night/Party |
| `play` `pause` `next` `prev` | — | AVRCP-транспорт |
| `test:all/l/r/woof/tweet/1-4/anti/sweep/off` | — | тест-сигналы |
| `tf:20-20000` | Гц | частота тест-тона |
| `status` `stats` `heap` `save` `reboot` `factory` | — | сервис |

### 3.3. Формат ответа `status` (для парсера)

Актуальный формат — 13 строк, контракт v35.1 в `protocol/status-contract.md`, раздел 2:

```
V0=40% V1=40% bal=0.00
Fc=400Hz hp=45Hz sub=ON
XO: Butter ON
TLF=0.00dB THF=-1.00dB
EQ: L=0.00 M=0.00 H=0.00
Mute: 0/0
SWP: 0
DUP: 0
BT: ON | SPP: OFF
Src: 44.1 kHz
Test: 0 TVol=4%
CHF: 0/0 0/0 0/0 0/0
Delay: 0/0/0/0
```

Парсинг регэкспами, устойчивый к пробелам; нераспознанная строка пропускается без падения.

## 4. Архитектура приложения

```
Compose UI (экраны, StateFlow-подписка)
        ↕
BiAmpViewModel  ←  парсер статуса  ←  LineReader (корутина, Flow<String>)
        ↓                                      ↑
CommandSender (очередь + троттлинг) → SppManager (RFCOMM-сокет)
```

- Одна Activity, три вкладки (Compose `NavigationBar`): **«Громкость»**, **«DSP»**, **«Сервис»**.
- Состояние соединения: `StateFlow<ConnState>`: `DISCONNECTED → CONNECTING → CONNECTED → RECONNECTING`.
- Вся работа с сокетом — на `Dispatchers.IO`.

## 5. Требования к Bluetooth-модулю

| ID | Требование |
|---|---|
| B1 | Только классический BT (SPP). **BLE не использовать.** |
| B2 | Список устройств из сопряжённых (`bondedDevices`); опционально поиск новых. |
| B3 | Подключение по UUID из п. 3.1; таймаут 10 с. |
| B4 | Фоновый цикл чтения: буферизация до `\n`, отдача строк во `Flow<String>`. |
| B5 | Отправка через очередь/мьютекс: команды не склеиваются и не теряются. |
| B6 | **Троттлинг ползунков:** не чаще 1 отправки / 150 мс; при отпускании — финальное значение всегда. |
| B7 | Автореконнект: 5 попыток (2/4/8/15/30 с), затем ручной режим. |
| B8 | Без соединения все органы управления заблокированы, кроме кнопки подключения. |
| B9 | Корректное закрытие потоков/сокета при выходе. |

## 7. UI/UX (Compose, Material3, тёмная тема)

### 7.1. Каркас
- Шапка: индикатор соединения (кружок + имя), кнопка Подключить/Отключить, при `RECONNECTING` — счётчик попыток.
- Ползунки: значение крупно; отправка по правилу B6.

### 7.2. Вкладка «Громкость»
| Элемент | Команда |
|---|---|
| Ползунок «Левая зона» 0–100 | `v0:` |
| Ползунок «Правая зона» 0–100 | `v1:` |
| Ползунок «Общая» 0–100 | `vol:` |
| Ползунок «Баланс» −10…+10 (тап по значению = 0) | `bal:` |
| Кнопки ⏮ ▶/⏸ ⏭ | `prev` / `play`/`pause` / `next` |
| Тумблеры «Mute Л/П» | `mute:0` / `mute:1` |
| Чипы пресетов Flat/Voice/Night/Party | `preset:0..3` |

### 7.3. Вкладка «DSP»
| Элемент | Команда | Диапазон |
|---|---|---|
| Кроссовер | `fc:` | 200–1000, шаг 50 |
| Сабсоник: тумблер + ползунок | `sub:` + `hp:` | 20–80, шаг 5 |
| Трим НЧ / Трим ВЧ | `tlf:` / `thf:` | −6…+3, шаг 0.5 |
| EQ Низ/Середина/Верх + кнопка «0» | `eql:` `eqm:` `eqh:` | −12…+12, шаг 1 |
| Перестановка Л/П | `swap:0/1` | — | перестановка левой/правой пары |
| Дублирование | `dup:0/1` | — | каналы 2,3 не выводятся |

### 7.4. Вкладка «Сервис»
- **Тесты:** НЧ / ВЧ / Каналы 1–4 / Антифаза / Свип / Стоп; поле частоты + «Применить» (`tf:`).
- **Диагностика:** карточка распарсенного `status` (автоопрос раз в 3 с при `CONNECTED`), кнопки `stats`, `meta`, `heap` → вывод в карточку лога.
- **Опасные действия:** `save`, `reboot`, `factory` — только через подтверждающий диалог.

### 7.5. Поведение при подключении
1. После `CONNECTED` отправить `status`, заполнить ползунки **без обратной отправки** (флаг `isSyncing`).
2. Автоопрос раз в 3 с; не затирать элементы, которые пользователь двигает прямо сейчас.

## 8. Надёжность и краевые случаи

| Ситуация | Поведение |
|---|---|
| Обрыв сокета во время перетаскивания | очистить очередь, снекбар «Соединение потеряно» |
| Ответ > 1 с | отправку не блокировать, опрос статуса пропустить |
| Мусор в ответе | строку игнорировать, писать в лог «Сервис» |
| Быстрые движения ползунка | троттлинг B6, очередь ≤ 10 команд, старые `vol:/v0:/v1:` вытесняются новыми |

## 9. 🔧 Подготовка среды и сборка (Windows + VSCode)

### 9.1. Установка (один раз)
1. **JDK 17:** `winget install EclipseAdoptium.Temurin.17.JDK` → проверить `java -version`.
2. **Android SDK cmdline-tools:** скачать *commandlinetools-win* с developer.android.com/studio, распаковать так, чтобы путь был `C:\Android\Sdk\cmdline-tools\latest\bin` (внутренняя папка **обязательно** `latest`).
3. В PowerShell:
   ```powershell
   cd C:\Android\Sdk\cmdline-tools\latest\bin
   .\sdkmanager.bat --licenses
   .\sdkmanager.bat "platform-tools" "platforms;android-35" "build-tools;35.0.0"
   ```
4. Переменные среды: `ANDROID_HOME = C:\Android\Sdk`, в `PATH` добавить `%ANDROID_HOME%\platform-tools`.
5. **Расширения VSCode:**
   - `Extension Pack for Java` (vscjava)
   - `Kotlin` (mathiasfrohlich)
   - `Gradle for Java` (vscjava)
   - `XML` (redhat) — для манифеста/gradle-файлов
6. В корне проекта создать `local.properties`:
   ```
   sdk.dir=C:\\Android\\Sdk
   ```

### 9.2. Сборка и установка (каждый раз)
В терминале VSCode (PowerShell), из корня проекта:
```powershell
.\gradlew.bat assembleDebug
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

### 9.3. Подключение Redmi (LineageOS, Android 15)
1. Настройки → О телефоне → 7 тапов по номеру сборки → включатся «Для разработчиков».
2. **Вариант USB:** включить «Отладка по USB», подключить кабель, `adb devices` — устройство должно появиться (для LineageOS драйверы обычно не нужны; если не видно — `sdkmanager.bat "extras;google;usb_driver"` и установка драйвера).
3. **Вариант без кабеля (рекомендую):** «Беспроводная отладка» → сопряжение:
   ```powershell
   adb pair <ip>:<порт-сопряжения>
   adb connect <ip>:<порт>
   ```
4. Проверка: `adb devices` показывает устройство → `adb install ...`.

### 9.4. Требования к репозиторию
- `README.md` с шагами 9.1–9.3 под Windows (PowerShell).
- Gradle Wrapper коммитится в репозиторий (`gradlew.bat`, `gradle/wrapper/*`).
- Проект должен собираться командой из 9.2 «с чистого клона» без правок.

## 10. Критерии приёмки

1. ☐ Проект собирается на Windows через `.\gradlew.bat assembleDebug` без ошибок.
2. ☐ APK ставится на Redmi (Android 15) по ADB (USB или wireless); разрешения запрашиваются.
3. ☐ Подключение к `ESP32 BiAmp Speaker`; статус-бар активен.
4. ☐ После подключения ползунки отражают актуальные значения устройства.
5. ☐ Ползунок громкости реально меняет звук.
6. ☐ `mute`, пресеты, транспорт работают (транспорт управляет плеером телефона).
7. ☐ Изменения `fc`/`sub`/тримов видны в следующем `status`.
8. ☐ Выключение колонки → `RECONNECTING` → автовосстановление после включения.
9. ☐ Быстрые движения ползунков: без зависаний, значения сходятся.
10. ☐ Тёмная тема, русский язык интерфейса.
